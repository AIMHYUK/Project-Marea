## 지켜야 하는 제약

### 레거시 `Input` 클래스를 쓰면 안 된다

`ProjectSettings.asset`의 `activeInputHandler: 1` — **Input System Package 전용**이다.
`Input.GetAxis()`, `Input.GetMouseButtonDown()` 은 컴파일은 되지만 실행 시
`InvalidOperationException` 이 난다.

```csharp
// 안 됨
if (Input.GetMouseButtonDown(0)) { ... }

// 이렇게
using UnityEngine.InputSystem;
if (Mouse.current.leftButton.wasPressedThisFrame) { ... }
```

`Assets/InputSystem_Actions.inputactions` 가 이미 있다 (Unity 6 기본 템플릿).
`Move` / `Look` / `Attack` 액션이 들어 있으므로 WASD·클릭은 여기에 붙이면 된다.

### NavMesh는 쓸 수 있다

`com.unity.ai.navigation` **2.0.9** 설치됨. 클릭 이동은 `NavMeshAgent`로 간다.

WASD와 클릭 이동이 한 캐릭터에 같이 있으므로 충돌 처리가 필요하다.

- WASD 입력이 들어오면 `agent.ResetPath()` 로 클릭 이동을 취소한다
- 수동 이동도 `transform.position` 직접 대입이 아니라 `agent.Move()` 를 쓴다.
  안 그러면 NavMesh 밖으로 나가서 다음 클릭 이동이 실패한다

## MCP for Unity

유니티 에디터를 Claude Code에 붙이는 브리지. **`Assets/MCPForUnity/` 에 v10.1.2 로
넣어뒀다** (`com.coplaydev.unity-mcp`, https://github.com/CoplayDev/unity-mcp).

### 왜 패키지가 아니라 에셋인가

원래는 `manifest.json` 에 git URL로 들어 있었다.

```json
"com.coplaydev.unity-mcp": "https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main"
```

`#main` 은 **버전이 고정되지 않는다.** 패키지를 다시 풀 때마다 다른 커밋을 물어올 수
있어서, 내 로컬에서도 브리지 버전이 조용히 바뀐다. 그래서 캐시에 받아진 10.1.2를
`Assets/` 로 옮기고 manifest 항목은 지웠다. 이제 버전이 움직이지 않는다.

**같이 바꾼 것**: 에셋 폴더에 들어간 `package.json` 은 패키지 매니저가 안 읽으므로
의존성이 따라오지 않는다. git 패키지가 끌어오던 `com.unity.nuget.newtonsoft-json` 을
manifest에 **직접 추가**했다 (3.2.2). 이게 없으면 MCP 쪽이 컴파일되지 않는다.

이전 manifest는 `Packages/manifest.json.bak` 에 남겨뒀다. `.gitignore` 에서 `*.bak` 을
빼놨으니 커밋에는 안 올라간다.

### 커밋하지 않는다

`Assets/MCPForUnity/` 와 그 `.meta` 는 `.gitignore` 로 제외했다. 게임 코드가 아니라
**에디터 도구**이고, 게임 쪽에서 참조하는 게 하나도 없다. 커밋하면 MCP를 안 쓰는
사람도 매번 컴파일하게 되고 버전 올릴 때마다 diff가 수백 파일로 잡힌다. 쓰는 사람이
각자 넣는다.

`.meta` 를 같이 빼는 게 중요하다. 폴더 없이 메타만 남으면 상대 쪽에 붙을 데 없는
파일이 굴러다닌다. "`.meta` 는 반드시 커밋" 규칙의 유일한 예외다.

`com.unity.nuget.newtonsoft-json` 은 manifest에 그대로 둔다. MCP를 안 받는 사람에게도
해가 없고, manifest가 사람마다 갈리는 게 더 골치다.

### 다시 넣는 방법

이 프로젝트를 새로 받아서 MCP를 쓰려면 유니티에서 Package Manager > Add package from
git URL 로 `https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity` 를 넣고,
`Library/PackageCache/com.coplaydev.unity-mcp@*/` 를 `Assets/MCPForUnity/` 로 복사한 뒤
manifest 항목을 지운다. 버전을 고정하려면 이 순서여야 한다.

### 붙이는 절차

1. 유니티 메뉴 `Window > MCP for Unity`
2. **Auto-Setup** — 클라이언트 설정을 대신 써준다. `claude` CLI가 PATH에 있어야 하고,
   서버 실행에 Python + uv/uvx 가 필요하다
3. Unity Bridge가 `Stopped` 면 **Start Bridge**

## 버전 관리

`(+8/31)` **저장소를 만들고 원격에 연결했다.**

```
origin  https://github.com/AIMHYUK/Project-Marea
main    → origin/main 추적
```

GitHub가 만든 초기 커밋(`README.md` + 템플릿 `.gitignore`) 위에 얹었다.
`git reset origin/main` 으로 히스토리를 이어붙였기 때문에 나중에
`unrelated histories` 로 막히지 않는다.

**`.gitattributes` 도 같이 넣었다** — 줄바꿈 규칙을 개인 `core.autocrlf` 가 아니라
저장소 안에 둔다. 설정이 다른 사람이 커밋하면 내용은 그대로인데 전 줄이 바뀐 diff가
생기고, 씬 파일에서 그러면 충돌 해결이 불가능해진다.
UnityYAMLMerge 설정은 각자 해야 해서 파일 안에 주석으로만 남겼다.

### 브랜치 전략 `(+8/31)`

- `main` — 항상 유니티에서 열리는 상태를 유지한다. **직접 커밋하지 않는다**
- `feature/<이슈번호>-<짧은이름>` — 작업 단위 하나에 브랜치 하나.
  예: `feature/1-agent-mover`
- PR로 머지한다. 본문에 `Closes #N` 을 넣으면 머지될 때 이슈가 자동으로 닫힌다
- 이슈는 `gh issue create`, PR은 `gh pr create` 로 만든다 (GitHub CLI)

⚠️ **씬 파일(`.unity`)을 건드리는 작업은 시작 전에 말한다.** UnityYAMLMerge를 아직
안 켰기 때문에 충돌하면 손으로 푼다. 아트가 씬에 오브젝트를 배치하는 동안 다른 사람이
같은 씬에 무언가를 넣으면 그때 터진다. 브랜치를 나눠도 이건 안 막아준다 —
**머지 시점에 똑같이 충돌한다.**

`.gitignore` 에서 일부러 **커밋하도록 둔 것**:

- `.meta` 파일 — 빠지면 팀원 쪽에서 참조가 전부 끊긴다
- `Packages/` (manifest, packages-lock 둘 다), `ProjectSettings/`, `Docs/`

제외한 것은 `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln`,
빌드 산출물, `*.bak`, 그리고 `Assets/MCPForUnity/` (위 참고).
**`Library/` 를 빼먹고 커밋하면 저장소가 수 GB로 불어난다.**
